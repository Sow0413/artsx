# 災害派遣

圏外を前提にした動き。測量の通常モードはそのまま残し、地図の「災害」をオンにしたときだけ、この中継と記録を使う。

## バケツリレー

近くの端末どうしは、いまの近距離セッション（サービス名 `survey-ptt`）を使う。運ぶものは `LinkFrame` の kind `bucket`。中身は位置、SOS、文字、被災箇所、通行のどれか一つ。

一通には次を付ける。

- 作った時刻と存在時間。位置は 10 分、SOS は 1 時間、文字は 6 時間、被災箇所と通行は 24 時間。中継しても存在時間は延ばさない。期限を過ぎた通は捨てる。
- ホップ上限。既定は 6。自分を数に入れて、上限に達したらそこで止め、次には渡さない。
- 通過した端末の ID。同じ端末が二度受け取ったら捨てる。同じ通を二度見たら捨てる。別のプロジェクトは捨てる。

新しい端末が近くに現れたら、まだ期限内で上限前の通だけを再送する。電池節約中は、この再送を 15 秒に一度までにする。通常は 2 秒。

SOS は、いままでの一本の近距離送信に加えて、この封筒にも載せる。119 の代わりにはしない。

## 通信が戻ったとき

箇所、通行、文字、各端末の最新位置のうち、まだ送っていないものを一つの束にする。`DisasterRelay` が届く印のときだけ渡し、渡した ID を `同期.json` に覚える。`箇所.jsonl`、`通行.jsonl`、`文.jsonl` は足すだけで、同期のあとにも書き換えない。

届く印は、端末の経路が satisfied になったとき。地上の回線でも、Starlink などの衛星回線でも同じ。衛星ルーターが Wi-Fi で端末の後ろにいる場合も、経路が戻ればこの印になる。アプリは衛星モデムの API を呼ばない。P510 の無線中継（`RadioLink`）の届く印とは分けてあり、災害の同期だけがこの経路を見る。

想定する受け口はまだ無い。

1. `POST /v1/disaster/sync` に束の JSON。
2. 写真の実体は、あとから `POST /v1/disaster/photos`。この版のスタブは JSON の控えだけを持つ。

P510 のホストが衛星回線の先にあれば、同じ口を使う。届かないあいだは端末の中継だけが動く。

## 被災箇所

現在地、種類（崩落、冠水、道路寸断、橋梁損傷、土砂、その他）、任意の写真、延長・幅・高さ（メートル、0.1m、空欄は未計測）。`記録簿/災害/箇所.jsonl` に一行ずつ足す。同じ ID は二度書かない。写真は `写真/` に一度だけ置く。中継する封筒に写真のバイトは載せない。ファイル名だけを渡す。

地図には種類のピンを出す。一覧は災害の画面。

## 通行

災害派遣がオンのあいだ、動いた跡を通れるとして残す。間隔は 25m。電池節約中は 80m。150m より離れた、または 15 分空いた点は線を切る。「ここで止まった」は通れない地点で、線には繋がない。地図では通れるを緑、通れないを赤で出す。同じプロジェクトの他の端末の線も、中継で届いた分を描く。

## 地図タイル

表示中の範囲は、いまの「この範囲を端末に保存」で地理院タイルを端末に書く。保存済みのタイルは圏外でも使う。電池節約中は、この追加保存を止める。

## 電池節約

オンのとき、位置の送信を 30 秒に延ばす（通常は 5 秒）。中継の再送は 15 秒。通行の点は 80m ごと。オペ画面も含め、画面の常時点灯をやめる。地図の追加保存はしない。

## 書き出し

`記録簿/災害/出す/` に置く。

- `被災状況.pdf` と `被災状況.csv`。日時、種類、緯度経度、精度、延長、幅、高さ、記録者、メモ、写真ファイル名。
- `写真帳簿/写真帳簿.pdf` と、同じフォルダへコピーした写真。災害査定の様式へ転記するための控え。

どちらも様式そのものは作らない。提出もしない。
