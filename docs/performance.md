# 性能

測量本体の最優先。現行の快測ナビは、現場が大きくなると遅く、固まる。ここはそれを超える。

おまけのスイッチには依存しない。座標簿、図面、測設、基準点、出力、実 SFC、重機のオペ画面が、大きい現場でも動くこと。

## 目標

- 延長 1km 以上の現場
- 座標簿 5 万点
- SFC / DXF は 10MB 級
- 図面のパンとズームは 60fps（一枚 16.7ms）
- 起動してから操作できるまで 2 秒。図面の解析が終わるのを待たない
- 測設のスナップ検索と、座標簿の絞り込みは 100ms
- メインスレッドを止めない

## 手段

図面の読込と解析は、画面のスレッドの外で行う。進捗は「図面を読んでいます」「図面を解析しています」「図面の索引を作っています」「図面を出しました」。解析のあいだも、プロジェクトは先に使える。

図形はグリッドの空間索引に入れる。何マスもまたぐ線は、全マスへ複製せず、範囲で当たるかだけを見る。スナップの交点は、タップに近い線から 48 本までに限る。

画面に出す線は、見えている範囲だけ、点の間隔まで間引く。全体が見えるときは代表だけを出す。一枚の上限は線 2000、文字 40。この線の束を Canvas にまとめて渡す。Metal へ渡すのも同じ束だが、この環境では GPU を測れないので、Metal の描画そのものは置いていない。地図への重ねも、図面の解析が画面を止めてからではなく、別のスレッドで作る。

座標簿は端末内の SQLite（`座標簿/book.sqlite`）。名前、種類、出典、段階、日付、緯度経度に索引を置く。画面の一覧は件数と先頭だけを読み、5 万行を毎回復元しない。書き出しはボタンのあと、画面の外で行う。以前の 1 点 1 ファイルは、SQLite が無い古い現場を読むときだけ使う。

保存は端末の中で終わる。座標簿も図面も、通信の返事を待ってから出さない。地理院タイルの取得は起動を止めない。

## 測り方

`SurveyCore` の `PerformanceTests` が、毎回の実行で `SURVEY BENCH` の行を出す。合成の DXF（延長 1km 以上、8MB 以上）と、5 万点の座標簿と、captain の実 SFC（`SurveyCore/Tests/Fixtures/captain-site.sfc`）を使う。

解析の時間は報告する。2 秒の目標は、解析の完了ではなく、既存の座標簿を開いて操作に入れるまで。スナップ、絞り込み、一覧、一枚のバッチは目標を超えたらテストが落ちる。実機の 60fps は、ここでは未確認。
