# 歩測と歩行推測

歩数で距離を出し、GNSS が弱いあいだは歩数で位置をつなぐ。測量本体で、おまけのスイッチには依存しない。段階は 0。測設の合格にはしない。バッジは「歩測」で、段階0〜3には入れない。

## 歩幅

身長を一度入れると、歩幅の初期値は身長×0.45になる。平らな所で分かっている距離を一度歩くと、その歩幅に替わる。例は 50m。開始と終了のあいだの歩数で、歩幅は道のり ÷ 歩数。5m 以上 500m 以下、5歩以上、歩幅は 0.3m 以上 1.5m 以下。外れたら採用しない。校正した日と、距離、歩数、歩幅は端末の中だけに残す。共有しない。持ち高さの校正と同じ「自分の校正」で行う。詳細は `docs/stature.md`。

斜面では、歩いた道のりに補正係数を掛ける。係数は 1/√(1+勾配²)。勾配 0 なら 1、勾配 1（45°）なら 1/√2。係数を手で入れると、そちらを使う。勾配を変えても、それより前の歩は書き直さない。

歩測の推定は、0.5m に距離の 2% を足す。50m なら 1.5m。この率は実機で測る前の設計値である。

開始と終了で距離を出し、終わりの点を種別「歩測」で残す。身長補正は掛けない。記録の段階は 0。方位が無い歩は、次に方位が付くまで保留する。方位が無いままなら距離は出ても、点は残せない。

歩数は CMPedometer。前面にいるあいだだけ、1秒ごとに問い合わせる。バックグラウンドでは数えない。歩数計が無い端末（多くの iPad、Swift Playgrounds）は、歩数を手で入れる。歩行推測は、その端末では始めない。

## 歩行推測

水平精度が無い、または 15m より粗いときは、歩幅がある場合だけ、歩数と方位と視覚慣性で位置をつなぐ。身長からの初期歩幅でも、既知距離の歩幅でもよい。歩幅が無ければ、弱い GNSS のままにする。8m 以内に戻ったら GNSS に戻し、「GNSSに戻りました。」と出す。8m と 15m のあいだは、今のモードを保つ。

視覚慣性は、丁張の相対高と同じ AR セッションを一つだけ使う。映像は保存しない。追跡を失っているあいだは、視覚の移動は足さない。方位が付いたとき、AR の +Z をその方位に一度合わせる。歩数のベクトルと視覚のベクトルがあるときは、平均を位置にし、差を推定誤差に足す。

歩行推測の推定は、1m に道のりの 3% を足したものと、歩数と視覚の差の斜辺。開始点は、切り替えたときの GNSS で、その GNSS の誤差は推定に足していない。戻ったときは GNSS の位置に合わせ、推測は捨てる。

地図の現在地、図面の現在地、オペ画面、接近警報の共有は、この位置と推定を使う。共有の精度は、推測中は GNSS の数値にしない。現場の範囲の外、作業時間の外、休憩中は、これまでどおり共有しない。観測の記録、基準点の FIX、身長、十字線の地盤高は、推測ではなく受信した GNSS を使う。

実機の歩数、方位、視覚慣性のドリフトは未確認。

## 位置出し

測設でタップした点までは、距離を個人の歩幅で割った歩数と、画面の上を前にした方向で出す。画面の例は「右まえ 16歩」。声は短く「前です」「後ろです」「右です」「左です」「右前です」で、数字は画面だけに出す。方向が変わったときだけ話す。切替距離未満は「もう少し前」、5cm以内は「そこです」。設定で数値も読める。既定は方向だけ。歩数とメートルも切り替えられ、既定は歩数。歩幅が無いときはメートルのまま出す。重機のオペ画面は、重機の進行か方位のままで、この声は使わない。この切替は端末の中だけに残す。実機の声は未確認。
