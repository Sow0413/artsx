# 測量

手軽に観測、手軽に測設。いつでも何処でも、測って出せる。

iPhone / iPad 向けの測量アプリです。地図タブ、作業ごとの精度の色、三角点での検証、取った点の引き継ぎが動きます。図面と出すは置き場所だけあります。

## iPad の Swift Playgrounds で開く

Mac も Apple Developer の登録も要りません。iPadOS 17 以降の Swift Playgrounds で、自分の iPad 上で実行します。

1. `測量.swiftpm.zip` を iPad に渡す。AirDrop、iCloud Drive、メールのどれでもよい。
2. ファイル App で zip をタップして展開する。
3. 出てきた `測量.swiftpm` をタップする。Swift Playgrounds で開く。開かなければ、共有から Swift Playgrounds を選ぶ。
4. 右上の実行で起動し、位置情報を許可する。

地図の地理院タイルは、最初の表示と範囲の保存に通信が要る。見本の基準点は同梱してある。カメラの利用目的は書いてあるが、撮影画面はまだない。

ソースを直したあとは `scripts/refresh-playground.sh` を実行し、`測量.swiftpm` を zip し直す。

## 今できること

- 地図に現在地と精度の円を出す。段階0は iPhone の GPS だけ。
- 地図の上で作業を切り替える。精度バッジの色は、今の精度が今の作業の要求を満たすかで決まる。
- 要求精度と、楽観的な報告にかける係数は「数値」から直せる。SitePack の JSON に残る。
- 国土地理院の標準地図を重ねる。見たタイルは端末に残り、表示中の範囲は「この範囲を保存」で圏外用に取っておける。
- 近くの基準点を地図に出し、同じ点を既定3回置く。各回の平均とずれ、回ごとの差、全体の平均、収束の線を出す。そろっていれば補正値にして、以後の観測から引く。作業の最後にもう一度置くと、戻り点検になる。
- 測るタブと地図から、今の作業で点を残す。下見の点は捨てず、作業種別と取得時の精度を残したまま、あとから測量点の座標に乗せ替えられる。
- 下のタブは 地図 / 図面 / 測る / 出す。図面と出すは次のスライスの案内。
- 座標、精度の判定、タイル、検証の統計は `SurveyCore` にあり、Linux で `swift test` できる。

## まだできないこと

- CLAS と RTK の受信機はつながない。型と、届く手段の目安だけ先に置いてある。
- 図面の DXF、PDF / DXF / SIMA の書き出しはない。
- 地点と軌跡の型はある。画面に出す記録は、作業で残した点だけ。
- 全国の三角点台帳は入っていない。同梱は見本だけ。
- 地理院タイルはアプリに同梱しない。最初の表示と、範囲の保存には通信が要る。
- この環境には Xcode がない。iOS アプリ本体も、Playgrounds のパッケージも、ここではビルドしていない。

## 精度の色

バッジの色は、今の水平・高さの精度が、今の作業の要求以内かどうかで決まる。同じ iPhone の値でも、下見なら緑、丁張なら赤になる。

| 色 | 意味 |
| --- | --- |
| 緑 | 実効精度が、水平も高さも要求以内 |
| 黄 | 要求は外れるが、2倍以内。高さが未取得のときも黄 |
| 赤 | 2倍より粗い |
| 灰色 | 位置がない、許可がない、水平精度が数値になっていない |

実効精度は、報告値に安全側の係数をかけた値。三角点の検証でその機器と補正が楽観的だったときだけ、係数は 1 より大きくなる。既定は 2。かけていないときは 1。

足りないときは「あと何 cm 足りないか」と、届く手段を出す。手段の目安は仮で、設定には出さない。三角点補正 0.50m／0.50m、CLAS 0.05m／0.10m、RTK 0.02m／0.03m、TS 0.005m／0.005m。水平と高さの両方が要求以内の手段だけ出す。丁張（2cm／1cm）に届くのは TS だけ。

測設に使ってよいかは、色とは別に見る。外部受信機の RTK Fix で、かつ色が緑のときだけ。iPhone や CLAS が下見で緑でも、測設の合格にはしない。

見本の iPhone（水平 約3m、高さ 8m）は、下見の高さ 5m に対して 2倍以内なので黄になる。水平 3.2m・高さ 4m の同じ端末は、下見で緑、丁張で赤。

三角点補正が有効なあいだは、その機器の判定を、ばらつきと目安 0.50m の粗い方で見る。概略なら緑になり、丁張は赤のまま。補正が古い、または別の機器のときは、報告の精度のまま判定する。

作業の仮の既定値は次のとおり。高さは、丁張だけ 1cm。ほかは水平と同じ。

| 作業 | 水平 | 高さ |
| --- | --- | --- |
| 下見・現況スケッチ | 5m | 5m |
| 概略の位置出し | 0.5m | 0.5m |
| 測量（トラバー） | 0.02m | 0.02m |
| 丁張・測設 | 0.02m | 0.01m |
| 出来形 | 0.05m | 0.05m |
| 境界・基準点 | 0.02m | 0.02m |

地図上部の「数値」で直す。保存先は Application Support の `SitePack/work-requirements.json`。楽観的だった機器は `SitePack/instrument-trust.json`。測地系の選択はない。

内部の段階は 0 が iPhone、1 が CLAS、2 が RTK、3 が併用。今つながるのは段階0だけ。

## 座標

端末の中は WGS84/ITRF の緯度、経度、楕円体高。画面下の注記は「JGD2024・下見／概略用」。測地系の変換は、出すときの一度だけにする。

取った点は `SitePack/field-observations.json`。`captured` が取得時の位置と精度、`adopted` が乗せ替えた測量点の座標。補正を引いた座標は `corrected`、戻り点検で割り振った座標は `closureAdjustment`。どれも `captured` は消さない。要再測は印だけ付ける。

## 三角点で検証

iPhone を、座標が分かっている三角点の上に置く。地図の三角印をタップし、回数は 1・3・5 から選ぶ（既定は3回）。1回ごとに置き直し、向きを変える。長さは1分・10分・30分（既定は10分）。1秒に1点、緯度経度と水平・高さの精度を残す。

回が終わるたびに、その回の平均とずれを足す。全部終わると、回ごとの差（再現性）と全体の平均を一覧にする。各回の線は、置いてからの経過時間に対する累積平均のずれで、水平と高さを描く。60秒のあいだの変化が水平・高さとも 2cm 以下になって、以後もそうなら、その時刻を「落ち着いた」とする。

回が2回以上で、平均のばらつきが水平 2m・高さ 3m 以下なら「この三角点で補正」を押せる。平均のずれを `SitePack/control-corrections.json` に残し、同じ機器の以後の観測から引く。取得時刻と経過分は常に出す。2時間を超えると黄色になり、判定にも座標にも使わない。高さの補正は、楕円体高どうしで比べられたときだけ。

作業の最後に同じ三角点へ戻って記録すると、始めの補正との差を出す。水平・高さとも 0.5m 以内なら「補正有効」。超えたら、途中の点へ時刻の割合で差を割り振るか、要再測の印を付ける。元の座標は残し、割り振った座標と印は別に持つ。

1回の中身は次のとおり。

- 平均位置。既知点を原点にした東西・南北の平均で、GRS80 の Vincenty 測地線から戻す。
- 水平の差。平均位置と既知点の測地線距離。
- 高さの差。既知の高さも楕円体高のときだけ、精度の判定に使う。成果が標高のときは、楕円体高から標高を引いた値を出す。ジオイドが含まれるので、楽観かどうかは判定しない。
- ばらつき。東西・南北の標本標準偏差を合成した値と、平均位置からの距離の95%。
- 報告精度。水平精度の平均が、平均位置の実際のずれより小さいとき「楽観的」。あわせて、68%の円（iPhone の `horizontalAccuracy`）の外に出た点の数。

CSV は記録の各行と、先頭の summary 行。共有シートから書き出す。

距離は GRS80（赤道半径 6378137 m、扁平率の逆数 298.257222101）の Vincenty。対蹠点で収束しないときはその点を捨てる。Karney の式は対蹠点向けなので、ここには移植していない。カメラの追従だけは、これまで通り球面の近似を使う。

見本は `SurveyApp/Resources/sample-control-points.json`（同じ内容の CSV もある）。日本経緯度原点の緯度経度と日本水準原点の標高は測量法施行令の値。富士山は公表されている緯度経度と令和7年の標高。机上の見本点は実在しない。全国の成果表は同梱しない。測量成果の複製には承認が要ることがある。

現場パックは、アプリの Application Support にある `SitePack/control-points.json`（無ければ `control-points.csv`）。`fgd_points.sqlite` から自分で切り出したファイルを、この形で置く。JSON の点は `id`、`name`、`kind`、`grade`、`latitudeDegrees`、`longitudeDegrees`、`heightMeters`、`heightKind`（`ellipsoidal` / `orthometric` / `unspecified`）、任意の `ellipsoidalHeightMeters`、`sourceNote`。楕円体高が入っていれば、高さの判定にそれを使う。ファイルが無いときは見本に戻る。

## 地図タブの参考

UX は **ジオグラフィカ（Geographica）** をモデルにした。株式会社エヌ・シィ・ティの日本向け地図アプリで、範囲を指定して地理院タイルを先に保存する、現在地を大きく出す、地点と軌跡を扱う、という使い方を借りている。コードは使っていない。

オフラインタイルの保存と、iOS で速く描く構成は **Organic Maps**（Apache-2.0）を参考にした。地域をひとまとまりにする、手元のデータを通信より先に見る、短いメモリキャッシュを置く、描画と保存を分ける、という考え方だけを Swift で書き直している。C++ と OpenGL の実装は移植していない。M0 の描画は MapKit。

OsmAnd と QField は GPL。それらのコードは読んでいないし、コピーしていない。

## 地理院タイル

- 実行時に `https://cyberjapandata.gsi.go.jp/xyz/std/{z}/{x}/{y}.png` から取る。
- 一度見たタイルはディスクキャッシュに残す。利用者が「この範囲を保存」した範囲は、現場パックとして別に残す。
- タイル画像はリポジトリに置かない。測量法上の複製をアプリへ同梱しないため。
- 地図の上に「地理院タイル」と「出典：国土地理院」を出す。

## 置き場所

- `SurveyCore/` — 純 Swift の計算。位置、作業の要求精度、タイル、範囲保存、地点と軌跡の型。
- `SurveyApp/` — SwiftUI。iOS 17 以降、iPhone と iPad の1つのアプリ。
- `測量.swiftpm/` — 同じソースを iPad の Swift Playgrounds で開くパッケージ。外部の依存はない。
- `project.yml` — XcodeGen の定義。`Survey.xcodeproj` は生成物なのでコミットしない。

## Linux でテスト

Swift 6.4.1（`.swift-version`）を入れる。

```bash
cd SurveyCore
swift test
```

55件。複数回の比較、収束、補正、戻り点検の割り振り、作業ごとの色、地理院タイル、検証の統計を見ている。

## Mac でビルド

Xcode 15 以降と、iOS 17 の SDK が要る。

```bash
brew install xcodegen
xcodegen generate
open Survey.xcodeproj
```

署名なしで確認するとき:

```bash
xcodebuild \
  -project Survey.xcodeproj \
  -scheme SurveyApp \
  -destination 'generic/platform=iOS' \
  -configuration Release \
  CODE_SIGNING_ALLOWED=NO \
  build
```

実機と TestFlight の前に、Apple Developer Program（年額の目安は約13,000円）へ加入し、Xcode の Signing で Development Team を選ぶ。`project.yml` にはチーム ID を書いていない。

## クラウド Mac と TestFlight

GitHub Actions（`.github/workflows/ci.yml`）は次の3つ。

1. Ubuntu で `SurveyCore` の `swift test`
2. macOS で署名なしの `xcodebuild`
3. 手動実行で `upload_testflight` を選んだときだけ、Archive して App Store Connect へ上げる

3に使う Secrets はリポジトリへ自分で置く。値はこの README にもワークフローにも書かない。

| Secret | 中身 |
| --- | --- |
| `DEVELOPMENT_TEAM` | Apple Developer の Team ID |
| `APPSTORE_ISSUER_ID` | App Store Connect API の Issuer ID |
| `APPSTORE_KEY_ID` | API キーの Key ID |
| `APPSTORE_PRIVATE_KEY` | API キーの `.p8` の中身 |

## 次のスライス

- 図面: DXF を重ね、2点で合わせる。RTK Fix になるまで、合わせは緑にしない。
- 測る: 作業で残した点はある。軌跡の記録はまだない。
- 出す: PDF、DXF、SIMA。JGD2024 への変換は、この出口で一度だけ行う。
- 現場パック: `fgd_points.sqlite` から近くの三角点を切り出し、楕円体高に直して `control-points.json` にする作業は事務所側。アプリは置かれたファイルを読む。
- その先: CLAS を Bluetooth で受ける。三角点での検証は、その受信機でも同じ画面で使う。
