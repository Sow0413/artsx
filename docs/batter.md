# 丁張

対象の高さに対して、今の測定高との差を画面中央の縦ゲージで出す。測量本体で、おまけのスイッチには依存しない。

目標は、図面の計画高にオフセットと勾配を足した値。オフセット +0.50m は、計画高より 50cm 上に貫を打つ。勾配は 1m あたりの高低で、向き（北から時計回り）が無いときは足さない。向きがあるときは、測設点から今の位置へ、その方位に沿った距離をかける。

測定高は二つから選ぶ。

- ポール先端。受信機の楕円体高からポール高を引く。ポール高が無ければ出さない。身長補正とは別の値で、身長の計算は変えない。
- 十字線の水平線。水平（±0.1°）のときだけ。器械高は地盤高 + 目の高さ。水平でなければ「高さになりません」と出す。

差が正なら高すぎるので下げ（赤、↓）。負なら上げ（青、↑）。絶対値が許容以内なら緑。許容は設定で、既定は ±5mm。作業一覧の「丁張・測設」の高低 1cm とは別。

大きな文字は「あと12cm下げ」。同じ文を読み上げる。残差が小さいほど間隔が短く、0 で 0.45 秒、1m 以上で 4 秒。実機の声とマナーモードは未確認。

平面の誘導は、測設点があるとき「現在地から距離、北から時計回り方位」をゲージと同時に出す。点が無ければ高さだけ。

残すと観測になり、種別は「丁張」。高さは決めた測定高で、身長補正は掛けない。精度の段階とバッジは常時出す。iPhone 単体は「目安」と書き、段階0、測設の合格にはしない。外部受信機なら、その段階を出し、目安とは書かない。

## 相対高

既知の楕円体高（基準点か座標簿）でゼロを合わせ、その後の高低を端末の動きで追う。標高だけしか無い点は使わない。視覚慣性（ARKit、重力方向が上）を主にする。気圧（CMAltimeter の相対高度）は補助で、追跡が弱いときは 7 割を視覚、3 割を気圧にする。どちらも無いときは IMU の鉛直加速度を積分する。映像は保存しない。

RTK FIX の GNSS が来たら、そちらを優先する。ポール高があれば先端、無ければアンテナの楕円体高。相対のバッジは出さず、受信機の段階を出す。FIX でない GNSS は使わない。

相対で追っているあいだのバッジは「相対」だけで、段階0〜3には入れない。測設の合格にはしない。記録に残す段階は端末の段階のままで、画面のバッジだけを相対にする。

推定誤差は、経過時間と移動距離と追跡の質から出す。設計値は、視覚慣性が 1mm/秒と 2mm/移動1m、気圧が 3mm/秒、IMU が 1cm/秒。質が弱いときは 2 倍。視覚と気圧の差も誤差に足す。20mm を超えたら「合わせ直して」。ちょうど 20mm はまだ許す。追跡を失ったときも合わせ直す。この率は実機で測る前の設計値である。

## 実機でのドリフト測定

計算の確認は Linux のテストで足りる。センサーのドリフトは、次の順で実機だけ測る。測るまでは未測定と書く。

1. 楕円体高が分かっている基準点に端末を置き、追跡が安定してからゼロを合わせる。
2. その場で 60 秒静止する。表示の高さと「推定 ±○cm」を、0 秒、30 秒、60 秒でメモする。
3. 同じ高さのまま約 10m 歩いて、同じ点に戻る。戻ったときの差と、移動距離、経過秒をメモする。
4. 高低差が分かっている 2 点（段差など、30cm 前後）を往復する。ゲージの差と、実際の差を比べる。
5. RTK FIX の受信機をつなぎ、同じ点で FIX の高さがゲージに出ること、相対のバッジが受信機の段階に替わることを見る。
6. 歩き続け、推定が 20mm を超えた瞬間に「合わせ直して」が出ることを見る。
7. メモした差が設計値より大きければ、`RelativeHeight` の率をその結果で見直す。見直すまでは設計値のままにする。
